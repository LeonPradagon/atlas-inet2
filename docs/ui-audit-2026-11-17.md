# Audit UI ATLAS — 17 November 2026

## Ruang lingkup dan metode

Audit menggunakan skill impeccable (audit), browser Codex pada aplikasi lokal, inspeksi DOM/CSS, dan pemeriksaan sumber. Audit ini tidak mengubah UI atau data operasional. Satu analisis uji dua titik dibuat untuk melihat kondisi hasil; formulir booking/pengguna/survei tidak dikirim.

Menu diperiksa: dashboard, peta jaringan, analisis alamat, analisis massal (kosong dan hasil tersimpan 11 lokasi), riwayat analisis, survei/verifikasi (daftar dan formulir yang sudah dalam survei), booking (daftar dan modal), audit trails, pengaturan, serta profil.

Pemeriksaan desktop memakai viewport override 1280 × 800; mobile memakai 430 × 850. Zoom browser menghasilkan lebar CSS mobile terukur 391 px. Tema terang diperiksa pada semua menu; tema gelap diperiksa lebih dalam pada analisis, riwayat, massal, survei, dan peta. Pengukuran mobile adalah emulasi viewport, bukan pengujian perangkat fisik atau gestur sentuh. Browser dikembalikan ke dashboard, tema terang, dan ukuran semula.

## Putusan integritas implementasi

**Belum konsisten sebagai satu sistem UI.** Komponen dasar reusable sudah ada, tetapi susunan formulir, cara membaca hasil, format angka, nama lokasi, dan posisi aksi belum menerapkan aturan yang sama. Bukti terkuat terdapat pada titik awal versus titik tujuan dan hasil satu titik versus dua titik.

Detector impeccable hanya memberi peringatan font Inter. Peringatan itu tidak dimasukkan sebagai masalah: mengganti font tidak menyelesaikan kebutuhan operasional pengguna dan berada di luar lingkup perbaikan ini.

## Temuan prioritas

### UI-01 — P1: Teks bantuan dan pagination kurang kontras

- Lokasi: `apps/web/src/styles.css:1175`, `apps/web/src/components/TablePagination.tsx:24`, `apps/web/src/dark-theme.css:159`.
- Bukti: helper light mode memakai `#9099a8` di atas putih: rasio sekitar **2,87:1**. Pagination riwayat dark mode terukur `rgb(108,117,125)` pada permukaan `#182336`: sekitar **3,36:1**. Target teks ukuran normal WCAG 1.4.3 adalah 4,5:1.
- Dampak: informasi wajib dan navigasi halaman sulit dibaca.
- Perbaikan: gunakan satu token teks sekunder yang memenuhi 4,5:1 pada masing-masing permukaan; audit `.text-secondary` juga, bukan hanya `.text-muted`.
- Perintah: `/impeccable harden`.

### UI-02 — P1: Modal booking belum menjaga fokus keyboard

- Lokasi: `apps/web/src/features/core-booking/CoreBookingPage.tsx:493`.
- Bukti kode: dialog custom memakai `aria-modal="true"`, tetapi komentar implementasi secara eksplisit menyatakan Escape dan focus trapping belum tersedia. Tidak ada pengelolaan fokus pada blok modal tersebut.
- Dampak: pengguna keyboard dapat keluar dari konteks dialog ke halaman belakang; menutup modal dan kembali ke pemicunya tidak dijamin.
- Perbaikan: gunakan dialog reusable dengan initial focus, focus containment, Escape, pengembalian fokus, dan penguncian scroll background. Verifikasi keyboard sebelum menyatakan sesuai.
- Acuan: pola dialog modal ARIA; periksa WCAG 2.4.3 dan 2.1.1 pada implementasi penggantinya.
- Perintah: `/impeccable harden`.

### UI-03 — P2: Nama lokasi A/B bercampur dengan Rute A/B

- Dampak: pengguna harus menebak apakah A/B berarti lokasi atau alternatif rute.
- Perbaikan: gunakan “Titik lokasi 1 / 2” di seluruh input, ringkasan, label ruas dan pesan; A/B hanya untuk alternatif rute.

### UI-04 — P2: Formulir dua lokasi memiliki pengalaman berbeda

## Pola sistemik dan hal yang perlu dipertahankan

- Pertahankan `DataTable`, `DetailTable`, fungsi judul kabel KMZ, dan komponen pemilih aset bertumpuk. Dasar reusable sudah tersedia.
- Pertahankan route lazy loading dan cleanup peta. Tidak ada bukti benchmark untuk menyebut seluruh aplikasi lambat.
- Tabel horizontal sudah berada di container yang bisa difokuskan keyboard; jangan memperbaikinya dengan menyembunyikan kolom/data begitu saja.
- Perlu satu format lokasi, angka, status, skala teks, komponen input lokasi, dan susunan hasil. Masalah terbesar adalah komponen gabungan yang belum seragam, bukan ketiadaan komponen dasar.
- Animasi sidebar mengubah `left` dan `margin-left`; profiling frame/reflow disarankan sebelum membuat perubahan performa baru. Ini risiko kode, belum temuan penurunan FPS yang terukur.
- Jangan mengganti font, mengurangi informasi teknis yang diperlukan survei, atau mengubah logika pemilihan terminasi sebagai bagian dari perapian UI.

## Kriteria pemeriksaan ulang

- Input titik lokasi 1 dan 2 menggunakan struktur, validasi, dan konfirmasi yang sama.
- Istilah A/B hanya untuk alternatif rute; tidak berulang sebagai nama endpoint.
- Desktop, tablet, dan mobile diuji pada CSS viewport aktual; detail lokasi dan aksi utama bisa ditemukan tanpa kehilangan konteks.
- Kontras teks normal minimal 4,5:1 pada terang dan gelap.
- Dialog dapat dibuka, diisi, dan ditutup dengan keyboard; fokus kembali ke pemicu.
- Seluruh informasi hasil lama tetap tersedia. Perubahan layout tidak mengubah terminasi, geometri, perhitungan panjang, atau status survei.
